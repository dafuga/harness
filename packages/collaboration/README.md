# Collaboration

Portable GitHub-backed project authorization, one-use invitations, and human comments. No executor or agent endpoint exists in this package.

`createCollaboration({ repository, source, cache, authorizeRepository, now? })` accepts only a server-verified Google actor as the separate first argument of each operation. `authorizeRepository` must prove that actor controls the selected installation/repository; installation IDs alone are not proof. GitHub owns projects, memberships, invitations and comments in an explicitly configured **private** repository and explicitly configured dedicated branch. The storage repository must already exist. If that exact branch is missing, the first owner-authorized project creation initializes a root commit containing only the configured records file; concurrent bootstrap retries without forcing or inheriting source files.

`createGitHubRepository({repository, ref, path, token, fetch?})` performs non-force Git updates and reloads records/membership on conflicts. The token callback must mint installation tokens restricted to the requested repository IDs and contents permissions. Invitation codes are returned once, stored only as SHA-256 hashes, and must be transported in request bodies; URLs contain only invitation IDs. This package performs no invitation delivery.

`createGitHubSource({token,fetch?})` returns `SourceHistoryAdapter`. Construct it **per authenticated request**, authorize the actor/project before every source or media operation, and discard it afterwards. Full-SHA commit/tree/blob promises are memoized only inside that instance; exact mutable refs are always fetched afresh. Failed reads are evicted. Ref reads require full `refs/heads/...` or `refs/notes/...` names (or full commit IDs). Trees fail closed on truncation; history paginates up to 10,000 entries and fails rather than silently truncating. LFS downloads verify pointer size and SHA-256 and use only approved HTTPS GitHub storage hosts.

`raw(repository, {commit, path})` returns defensive copies of exact Git SHA-1-verified blob bytes, including unmaterialized LFS pointers. `read` materializes those verified pointers. Cache consumers must bind plain bytes to the selected tree's Git blob hash; expected artifact SHA-256 alone is insufficient. Materialized LFS bytes must match the verified raw pointer's object ID and size.

`historyPage(repository, {commit, paths, page?, perPage?})` reads a bounded page for up to 64 owned paths at an exact full commit, with four concurrent requests and 1–100 entries per path (default 30). GitHub Link headers determine `complete` and `nextPage`; overlapping paths are deduplicated within each page. Consumers must also deduplicate hashes across pages. This avoids enumerating ancestry trees. Callers remain responsible for authorizing ownership of supplied paths.

`getProject` reports the exact collaboration records revision read; `createProject` reports its accepted commit. These summary fields are never persisted in project records. Projection cache identities include `collaborationRevision` so comments and membership updates invalidate cached JSON even when source is unchanged; omitted legacy values normalize to null.

Cache helpers partition principal/project/repository, requested ref, source commit/tree, notes/evidence refs and revisions, history-index revision, artifact hash and profile. Missing provenance uses explicit nulls. Hash-mismatched entries are discarded. Cache reads never authorize membership or writes; deleting the entire cache loses no authoritative records. Source snapshots/DTO projection and Google session verification belong to the server integration.

Run `HARNESS_CLI_PATH=../../src/index.ts bun run check`. Tests use synthetic HTTP responses and disposable in-memory caches; no real GitHub, provider or credential writes occur.

`rawMany(repository, {commit, paths})` batches textual metadata in sequential GitHub GraphQL requests of at most 64 paths. Each result must match the selected repository ID, exact tree blob OID, UTF-8 byte length and Git SHA-1. Binary, truncated, missing and partial-error responses fail closed. Request-local raw/read promises share the verified bytes; returned maps contain defensive copies. GraphQL JSON is streamed with a strict 16 MiB limit.
