## Scope and delivery forecast

Daniel can run his daily Tracker, session, approval and release workflows from Harness Studio on iPhone and Harness on Mac. Shared project browsing, project chat, and operational control remain available under their existing distinct grants. The scope covers the owner actions in the inventory below for enrolled hosts and configured release targets. Host service installation, cutover, database repair, credential setup, raw journal and transcript export, destructive administrative deletion and arbitrary terminal access remain operator runbooks.

| First useful phone cut            | **1–4 December** (6–9 working days)        | Open the Needs you list, read the item, flag or answer it, review and decide a registered, exact-release approval request, approve or deny a paired Vault request with Face ID, and launch one Tracker task on an eligible host. All actions show their authoritative receipts or an explicit pending/refused state. |
| Full iPhone and Mac owner control | **4–15 January 2027** (6–8 calendar weeks) | Run every in-scope row below, including stop/resume, bounded session output, Chief of Staff and agent replies, push to the correct request, deploy go and rollback on qualified targets. Provider adoption beyond qualified targets gets its own rollout date.                                                       |

The forecast assumes two implementation lanes, one for shared UI/native releases and one for Tracker host/release integration, plus timely security review and one owner device session per release. The first cut needs a fresh authoritative Tracker path, typed launch, release decision receipts, and a signed physical iPhone Vault check. A decision becomes usable for real releases only where the runner consumes its receipt. These are roughly 3–5 days for Tracker inbox/launch, 3–5 days in parallel for decision/Vault integration, and 2–4 days for integration, signing and owner acceptance. The full cut adds roughly 3 weeks of parallel session, chat and Tracker workflows, plus staged deploy/rollback qualification and a holiday/release buffer. An Apple capability/signing delay, unavailable owner acceptance, or blocked deployment pilot moves the affected date. With one implementation lane, allow roughly 2–3 weeks for the first cut and 8–10 weeks for full parity. These are planning estimates with unassigned implementation capacity.

## Operator contract

- **App path.** Start at Home and follow Needs you, a project card or an approved notification to the exact item, release or run. An item detail shows current question, timestamps, retained notes, run state and refresh. Give each screen one main list or detail and put review in a shared dialog or phone sheet. Desktop uses the same records and action labels. Use the existing Project chat composer for project conversation.
- **Tracker and host authority.** Route Tracker actions to the native hub through the paired encrypted channel on iOS and the verified local or paired authority on Mac. A Google account establishes owner identity. Grants for Tracker reads, Tracker actions, agent control, release approval and Vault stay distinct, bound to the actual actor and device or host. Publish only a redacted projection to Hub and the replica. A change of grant invalidates outstanding work and stale scopes.
- **Writes and receipts.** Reuse the outbox for confirmed Tracker notes, flags and answers. Bind an answer to the current flag token. Each intent carries an idempotency key, target ID, expected version and actor. Show queued locally, acknowledged, conflict, refused and unknown outcome distinctly. Reconcile an interrupted request against its receipt before another attempt. Launch, stop, Vault decisions, deploy approval and rollback require an online, fresh review of one immutable target. Duplicate, expired, revoked, wrong-environment and stale requests fail closed.
- **Sessions and messaging.** A launch previews the Tracker item, approved project/ref and eligible host/model. Show queue/admission then real run ID. Withdraw affects queued work. Stop targets one live run generation, requests graceful shutdown, records reason/exit and exposes escalation under a separate confirmation. Resume uses recorded context and a new acknowledged attempt. Output is a bounded, redacted tail with truncation and freshness. Agent and CoS messages identify the recipient and exact session generation, show delivery acknowledgment, and associate replies with the same thread. Use typed host operations and retain the existing controls over provider execution.
- **Approvals and releases.** Vault approvals bind the exact request, executor, device and expiry. Show only safe metadata and keep credential handling in the reviewed broker/native path. Release decisions show project, environment, source SHA, artifact/release ID, parity, prerequisites, smoke evidence and rollback target. Apply go or rollback only through a registered script runner and bind its separately authorized one-time execution claim to that exact plan. A Tracker answer may link to an approval receipt. The approval authority is the typed decision service. Production requires Daniel's specific release authorization and existing project gates. Rollback requires its own plan, compatibility check and authorization where the original approval did not cover it.
- **Alerts.** Send opaque request references and safe notification copy. Fetch and authorize content after app open. Tapping an alert opens review. An expired/revoked notification shows an unavailable state. A foreground refresh still serves a complete first cut while APNs is being qualified.
