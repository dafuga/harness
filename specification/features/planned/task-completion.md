# Feature: Task Completion

## Overview

Harness provides opt-in coding and planning audits using committed source and actual evidence. Runtime profiling remains separate from performance budget approval. Structural heuristics expose missing proof and retain uncertainty.

## Acceptance Criteria

- Coding completion requires intact verification of the exact committed source and matching representative latency and memory observations for affected executable units.
- Planning completion checks substantive proposal sections, acceptance items, dependencies, verification and performance plans without executing hypothetical implementation work.
- Explicit observation APIs preserve one-pass effects, receivers, returned values and promise identity. Replayed benchmarks require explicit caller-selected workloads and counts.
- Standard test-runner profiling observes only eligible registered source, excludes its own bootstrap and explicit benchmark boundaries, and leaves production build artifacts unchanged.
- Missing or unsupported source attribution, stale observations, failed operations and incomplete scopes never become successful measurements.
- The CLI and public verification API share the same checks. Loops opt in explicitly with `--kind coding` or `--kind planning`; existing loop, agent and Desktop completion behavior stays unchanged.
- Recent catalog controls, cards, Layouts, helper links, loading states and config behavior remain the current main implementation.
- Existing historical evidence remains readable; absent profiling cannot satisfy a new completion claim.

## Dependencies

Reuse the current verification stores, unit registry, capture protocol and loops. Preserve the existing agent and Desktop run services. Preserve registered identities and published verification entrypoints. Do not change deployment topology or adopt an older UI implementation.

## Verification

Run the existing task, loop, activity, verification, source-runner and Desktop behavior matrices. Cover missing proof, stale source, incomplete plans, cancellation, private data exclusion and native Bun/Node boundaries. Run the full repository check and affected browser flows before landing.

## Performance

Retain actual source measurements and representative timing and memory observations from the final committed tree. Label whole-process RSS and runner overhead accurately. Explicit sampling does not approve a performance baseline or attribute process memory to one function.

## Future Enhancements

External agents that never call Harness cannot be prevented from making an unsupported chat claim. The audit reports its heuristic limitation and preserves the need for acceptance review.
