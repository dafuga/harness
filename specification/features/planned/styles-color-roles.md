# Feature: Styles Color Roles

## Overview

Styles explains the existing palette by intended role so component authors and coding agents can select the appropriate CSS variable. The guide complements the complete token catalog and preserves the established app palette and action semantics.

The current standardized Styles tests prove token names and categories are complete, but never require role labels or usage guidance. A raw inventory therefore passed while authors still had to guess which color to use.

## Acceptance Criteria

- A clearly labelled Color roles region identifies primary and secondary roles, surfaces/backgrounds, text hierarchy, and success, warning and error treatments.
- Each role names real canonical variables and explains what to use them for. Guidance agrees with current shared controls; decorative accents do not imply unsupported action semantics.
- Colors and examples resolve existing app tokens, with no new literal paints or unrelated component redesign.
- Desktop, tablet and mobile use the same guide without horizontal overflow. Extend the existing Styles route, evidence and standard component-catalog tests.
- Keep agent guidance synchronized with the role definitions. Full CLI/native verification remains deferred; the current combined preview batch stays separate.

## Future Enhancements

- An actual theme redesign or new brand palette requires a separate request.
