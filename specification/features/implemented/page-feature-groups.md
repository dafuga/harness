# Feature: Page Feature Groups

## Overview

Organize the Pages catalog by the feature folders that own its routes. Keep each
feature's list, detail and history pages together. Teach agents the same approach
through Harness scaffold guidance and generated project instructions.

## Acceptance Criteria

- Components, Configs, Helpers, Layouts, Models, Pages and Services each contain
  their three registered visual routes; Platforms contains two and Styles one.
- Existing route URLs, registered unit IDs, shared cards and screenshot identity
  remain stable. Generic navigation pages keep their existing category.
- Generated app and library AGENTS/skill instructions and page/view guidance
  require feature folders and explain URL-preserving route groups.
- The standard category browser scenario proves the headings at desktop, tablet
  and mobile, retains before/after images, and reports no unexpected errors.

- Shared models keep their identities, source filenames and classification. Their
  names omit the `.types` suffix on cards, links and detail headings. Generated
  guidance teaches the same logical naming rule.

## Future Enhancements

Other applications can extend their own project taxonomy as their features grow.
