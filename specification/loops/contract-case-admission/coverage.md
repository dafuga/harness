# Contract admission controls

The existing validator method case previously modeled a function as a service,
never removed all state declarations and never contradicted a helper Example's
result. The contract comparison case did not test case growth through new prop or
error names. Generated guidance did not explain that existing rows should be
strengthened for those inputs.

Keep the existing one validator, two contract-service and eight guidance cases.
Use a real indexed Runner class and a separate indexed rank function. Collect all
negative admission observations before the assertion so a first mismatch cannot
prevent the other controls from running. The ten controls cover contradictory
helper result/input/call, an unowned callable, omitted or duplicate states,
a non-method subject, unsupported class result forms and a function masquerading
as a class. Comparison observes both prop-based and error-based count inflation.

The first characterization has four product failures and seven passes across the
same 11 cases. The final failing checkpoint must be retained before product repair.
The intended repair requires declared states, real method subjects, compatible
class result expectations and one consistent authored source for helper Examples.
Case identity comparison must reject extra existing-state rows created merely by
naming another prop or error. Shared generated guidance and repository skills must
state the same rule. Broader migration and normal verification remain separate.
