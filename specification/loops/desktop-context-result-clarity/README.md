# Desktop context and result clarity

The standard component catalog checked disabled project controls, revision timestamps and loaded evidence, but did not require visible busy/context labels or distinguish assertion and output disclosures. The gate fixture also supplied a generic shared child paragraph unrelated to project activity.

The existing cases now require:

- ProjectGate has no generic activity announcement; busy opening has a visible label and busy semantics.
- RevisionPicker exposes Branch/Commit words, the selected environment, distinct historical/pinned context and a neutral navigation button at each viewport. A pinned tip offers Follow branch instead of Go to tip.
- RuntimeBehavior presents one assertion disclosure per test. Output artifacts use a distinct caption while retaining all original recorded contents.

The fixture-only child removal and the missing existing output-artifact state belong in the test checkpoint. Product repairs follow a committed failing run. Keep the test corpus unchanged for the matching green run. Passing focused captures and partial entity verification remain separate evidence types.
